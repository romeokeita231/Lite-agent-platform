# HMAC 密钥不落库

Status: accepted

`agents.secret_env` 存的是**环境变量名**，不是密钥本身。平台从自己的进程环境读值，用原文计算 HMAC-SHA256。数据库里没有任何可用于冒充平台的东西。

## Considered Options

- **库里存哈希**：HMAC 必须用原文计算，哈希存储在算法上不成立。
- **库里存密文**：需要平台持有一把解密钥匙；那把钥匙最终仍要放在环境里或配置里，只是把同一个问题推后一层，还多了一套轮换与泄漏面。

## Consequences

- 加一个 Agent 需要在平台侧配好对应的环境变量，而不是只发一条 SQL。这是有意的摩擦：凭证的放置位置决定了数据库备份泄漏时谁会失守。
- 环境变量未配置时，该 Agent 的 Run 直接 `failed` + `policy_unreachable`，不重试到超时。缺少凭证与 Policy 不可达在运维上是同一类错误：平台没有能力完成这次决策。
- 密钥轮换是两个动作：改平台环境变量、重启；`agents` 表不需要更新。
