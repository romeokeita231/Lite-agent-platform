# Span 与 Checkpoint 同库同事务

Status: accepted

01 项目有一条相反的 ADR（轨迹写 MongoDB、写失败不阻塞业务）。那条在那边成立，因为业务正确性只写在 PostgreSQL，轨迹用于复盘。这里不成立：可观测性是平台交付物本身（模块④），一条"账上有、链接上无"的 Run 直接推翻平台对外的承诺；而且 Checkpoint 与它的 Span 在同一时刻产生，拆到两个存储只多一份对账工作。所以 Span 与 Checkpoint 同一事务写入。

## Consequences

- Span 写失败会让 Step 失败，进而走重试。这是**有意的**，不是缺陷——必须写进 ADR，否则将来有人会把它"优化"成旁路。
- 单库单事务，没有跨库一致性问题，也不需要为轨迹准备第二种存储。省下的不只是代码，还有"两个库对不上时以谁为准"这个问题本身。
- 代价：PostgreSQL 同时承担账本与轨迹，是写入热点。demo 规模下无所谓；真到量级压垮它时，优先按时间分区，而不是换库。
