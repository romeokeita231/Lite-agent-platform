# 平台与策略都是 Go，进程边界保留

Status: accepted

JD 只需要「精通 Python 或 Go 中至少一种」，Go + Python 的分工从来不是 JD 的要求，而是原提案 §0.3 里一条自我标注为"建议、不构成已定决策"的选择。它给 Python 的唯一技术理由是 LLM 生态成熟，而 ADR 0005 把所有模型调用收归平台之后，业务侧不再接触任何 LLM SDK —— 这个理由在架构定稿的那一刻就失效了。因此：平台、参考 Policy、SDK 全部用 Go，不交付 Python。

## 保留的部分

进程边界不因为语言统一而消失。平台仍然通过 HTTP 调用 Policy，理由不是语言，是两件事：平台不能在自己的进程里执行业务侧代码；业务策略必须能独立发版、独立重启，而不牵动平台。这两条与语言无关，所以"纯 Go"并没有拿掉这条边界，只是拿掉了第二个运行时。

## Consequences

- 一个工具链、一套构建、一个调试循环。省下的时间按 30–50 小时计，来自少一套运行时、少一套依赖管理、少一处跨进程问题要查。
- 面试叙事换掉：「平台团队用 Go、应用团队用 Python」描述的是**别人公司的组织结构**，0 年经验的人守不住。「平台不执行租户代码，决策在独立进程里，契约与语言无关」描述的是**自己写的边界**，守得住，并且顺带保住了"跨语言"这条加分项——契约是 HTTP，换个协议实现方不需要平台改一行。
- 失去全部 Python 证据：作品集里 Python 只剩简历上的一句话。这是明码标价的代价，不是遗漏。
- §2.3 的 Platform Python SDK 与"两个示例 Agent 合计 300 行 Python"作废。示例 Agent 改为两个实现了同一 Policy 契约的 Go 程序。
