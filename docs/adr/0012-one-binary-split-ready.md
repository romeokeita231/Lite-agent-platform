# 交付一个二进制，把可拆分性当交付物

Status: accepted

原计划按模块拆成多个服务。改为交付 `platform` 一个二进制，内部四个包（runtime / model gateway / tool gateway / observability）只通过接口互相调用；另有 `policy-example` 与 PostgreSQL 两个容器。拆成四个进程的一次性成本估 20–30 小时，之后每个功能多一成多的摩擦，换来的是"服务间隔离"这句话——而这句话在面试里经不起一句"这两个为什么该拆"。

## 隔离不是进程数量问题

真正值钱的是三组可演示的性质，进程数不等于其中任何一组：

- **租户之间**：每租户并发上限 + token bucket。一个租户打满时，另一个租户的延迟不变。
- **故障域**：工具端点 hang 住，Run 在超时后失败，其他 Run 不受影响。
- **依赖域**：Policy 进程被杀，Run 走重试；平台重启，Run 从账本续跑。

三条都能用一条命令演示，而且比"我拆了四个进程"更难被问倒——因为没有追问的缝隙。

## Consequences

- 包边界必须画成"可提取"的形状：包之间只走接口、不共享内部类型、不跨包读配置。所以真需要拆的时候它是两小时的活，不是重构。
- 如果最后非要拆一个，拆 Tool Gateway：它是唯一和外部不可信端点打交道的组件，有真实的出口控制、超时与配额理由。而且是最后拆，不是先拆。
- 部署仍然给两个 Deployment（platform 与 policy）。K8s 的叙事不需要四个服务才成立。
