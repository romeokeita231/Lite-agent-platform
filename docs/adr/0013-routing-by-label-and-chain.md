# 路由是标签加有序链，不是评分

Status: accepted

请求侧用路由标签（`route:cheap` / `route:fast` / `route:default`），租户为每个标签配置一条有序模型链；解析就是查表取链，永远从第一个开始试。按实时延迟或成本动态打分的方案被排除。

## Considered Options

- **动态评分**：demo 规模下只会制造不确定性，而且会让"这次为什么走了这个模型"失去唯一答案——而这正是 ADR 0003 承诺要能回答的问题。

## Consequences

- 同样的请求在同样配置下永远走同一条链：可复现、可解释、可以写进文档。
- 路由决策必须落进 `model_call_logs`——请求的标签、解析出的整条链、最终生效的模型。少记一样，事后就解释不了。
- 标签是平台定义的固定集合，租户只能配链、不能造标签。放开标签等于把"这条链为什么这么排"的责任推给租户，平台就不再持有可回答的答案。
