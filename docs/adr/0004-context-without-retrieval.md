# 平台提供上下文，不提供检索实现

Status: accepted

JD 的"执行上下文、会话状态、记忆存储和知识检索"在原设计里被挂到"模块①的扩展部分"，但 M 档清单里一行都没有——这是静默砍掉，不是决策。本平台的做法：上下文组装与会话状态由平台提供（它本来就是 Checkpoint 的副产品），检索以可插拔接口的形式暴露，默认实现只做关键词匹配。

## Consequences

- 可以诚实地说"平台提供了检索接口，具体索引留给上层"，而不必说"没做"。
- 明确排除 embedding 索引、pgvector、rerank。理由不是工时，是定位：那会把项目重心拽向 RAG，而 RAG 是另一个交付物的主场，两者约定不构成组合。
- 若将来要做真实检索，接口不动，只换实现。
