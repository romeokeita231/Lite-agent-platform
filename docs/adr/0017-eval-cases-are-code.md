# 评测用例是代码资产，平台只存快照

Status: accepted

用例存仓库（`cases/*.yaml`），随请求提交、平台把它**原样快照**进报告；平台不建 `eval_case` 表。断言声明式：期望终态、期望的工具调用序列（子序列匹配 + 参数子集匹配）、期望输出字段。

## Consequences

- 报告自包含。用例后来改了，历史报告仍然解释得清自己——这是"存快照"而不是"存引用"的全部理由。
- 子序列 + 子集匹配是刻意的宽松。写死"第 3 步必须调 `query_order` 且参数完全相等"，会让任何一次无关的参数增加都判失败，最后没人看报告。
- 评测跑的是真 Run，所以它进不了 CI：CI 不该花 token，也不该 flaky。评测是手动或定时任务。
- 平台一旦存用例，就多出一份会漂移的真源，而且它和被测 Policy 不在同一个 commit 里。这条要写进文档，否则将来有人会"顺手"加个用例库。
