# 上下文由平台裁剪，Policy 只声明保留

Status: accepted

每一步问 Policy 时，平台给的是"最近 N 步完整 + 更早的一行摘要"的窗口化账本。Policy 在上一步的返回里用 `keep: [step_index...]` 声明它想留哪些，裁剪与计量都由平台做。

## Considered Options

- **全量账本**：token 随步数线性膨胀，正好撞在"上下文长度优化"这个考察点上。
- **平台自己判断相关性**：平台猜 Policy 需要什么。猜错了没人能解释，也复现不了。

## Consequences

- 裁剪必须可复现：同样的账本 + 同样的 `keep` 声明，必须裁出同样的视图。否则恢复之后 Policy 看到的上下文与崩溃前不一致，它会做出不同决策，而账本上没有任何东西能解释这个差异。
- 上下文 token 单独计量（不是模型调用的 input tokens，而是平台裁出来的那一份），否则"上下文工程省了多少"永远证明不了。
- `keep` 是声明不是命令：平台可以因为窗口上限拒绝保留，并回一个 `dropped` 列表。Policy 必须能接受自己被削减。
